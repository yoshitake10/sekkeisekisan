# 設計積算ツール データ様式仕様書

空調換気設備 設計積算ツール（本リポジトリ）が **受け取る／書き出す** データの様式をまとめたもの。
各項目の根拠はコードの `ファイル:行` で示す（基準コミット: `4e7dea3`）。
数量表・単価マスタ・見積書の受け渡し（Excel/CSV/JSON）を他システムや社内資料とつなぐ際の参照用。

> 「必須」の意味について: 本書の「必須」は TypeScript 型上の必須（`?` なし）を指す。**プロジェクトJSON読込時に実行時検証されるのは `rooms` が配列であることだけ**で、他の欠損はブラウザ再読込時に既定値で補完されるまで `undefined` のまま動作する（§2.0）。CSV/Excel 取込の「必須」は列の対応付けと値の空判定が実際に行われる（§4, §5）。

## 2. プロジェクトJSON（`*.sekisan.json`）

### 2.0 読込・書出しの規則

- **書出し**: プロジェクトページ「JSON書出し」。`JSON.stringify(project, null, 2)`、ファイル名 `<案件名>.sekisan.json`（案件名が空なら `project.sekisan.json`）。 `src/pages/ProjectPage.tsx:22-29`
- **読込**: 同ページ「JSON読込」（`accept=".json"`）。検証は **`rooms` が配列であることのみ**（それ以外は「形式が不正です」）。 `src/pages/ProjectPage.tsx:31-45`
- 読込時は `{ ...createProject(p.name || 'インポート'), ...p, id: genId('prj') }` で取り込む。 `src/store.ts:245-248`
  - `id` は **必ず再採番**される。
  - **トップレベルの欠損キー**は `createProject()` の既定値で補完される。ただし `"name": ""` や `null` はそのまま保持（`インポート` になるのはキー欠損時のみ）。
  - **`rooms` の各要素・`estimate` の内側は読込時には補完されない**。欠けたまま機器選定を開くと負荷計算が NaN になり、見積タブでは `notes.trim()` 等で描画エラーになる（`src/logic/selection.ts:54`, `src/pages/EstimatePage.tsx:647`）。ブラウザ再読込後に `loadPersisted` が補完する（§3）。渡すJSONは 2.1〜2.6 の必須キーを埋めること。
  - `updatedAt` は読込時に更新されない（ファイルの値がそのまま案件一覧に表示）。
  - 参照先 id（`usage`→LoadUnit、`selectedModelId`→DaikinModel、`unitPriceRef`→UnitPrice、`drawingId`）の整合は検証されない。
  - 数値キーの型検証はない（文字列を渡すと演算時に暗黙変換される）。**number は number で渡す**こと。
- 単価マスタ・原単位・機器DBは **プロジェクトJSONに含まれない**（ブラウザ単位、§3）。`unitPriceRef` はJSONに残るが、参照先マスタが無い環境では解決できない。

## 3. ブラウザ内永続化（localStorage）

- キー `sekkeisekisan_v1`、400ms デバウンスで保存。 `src/store.ts:22, 111-133`
- 形: `{ projects: Project[], activeProjectId, daikinModels: DaikinModel[], loadUnits: LoadUnit[], roughCosts: RoughCostUnit[], unitPrices: UnitPrice[] }`（`PersistShape`, `src/store.ts:24-31`）
- 読込時（`loadPersisted`, `src/store.ts:89-107`）に旧データを補完: `estimate` は `defaultEstimate()` とマージ、`rooms` の各要素は `createRoom()` とマージ、`quantityItems/measurements/drawings` は `[]` 補完。**マスタ4配列（`daikinModels/loadUnits/roughCosts/unitPrices`）は補完されない**（欠けた保存データを外部から書き込むと例外の原因になる）。
- 別タブの保存内容は `storage` イベントで同期されるが、このとき補完は行われない（`src/store.ts:348-372`）。
- 保存失敗（容量不足）時はバナー表示。**PDF/DXF ファイル本体は保存されない**（メタのみ）。

### 4.1 列マッピング（自動判定の見出し語）

| key | 見出し（完全一致を優先） | 別名（部分一致も可） | 必須 |

| `category` | 分類 | カテゴリ, 種別, 工種, 科目 | |
| `spec` | 規格 | 仕様, 型番, 型式, サイズ | |
| `unit` | 単位 | | |
| `quantity` | 数量 | 員数 | |
| `unitPrice` | 単価 | 複合単価, 単価（円） | |
| `remarks` | 備考 | 注記, メモ | |

自動判定の規則（`src/io/ImportMappingDialog.tsx:46-75`）:
- 見出しセル側の空白（半角・全角）を除去してから比較する。したがって見出し `名 称`・`名　称` は `名称` として一致する。コード上の別名 `名 称` `規 格` `単 位` `数 量` `単 価` `備 考`（空白入り）は実際には一致しない。
- フィールド定義順（name → category → spec → unit → quantity → unitPrice → remarks）に、**完全一致 → 部分一致**の順で最初に見つかった列を割当てる。割当済みの列は再利用しない（最大52列）。
- 部分一致の副作用例: `工事項目` は name の別名 `項目` に、`機種別` は category の別名 `種別` に取られうる。判定結果は手動で変更できる。

- モード: `append`（追記）／ `replace`（全置換、確認ダイアログあり。キャンセルすると何も保存されずダイアログは残る）。
- **単価が数値でない行（「別途」「時価」、全角 `￥` 付き等）はスキップ**され件数が通知される。取込 0 件なら中止。単価の負数・0 は検証されない（0 円以下は引当対象外、§6）。
- `category` 空 → `その他`、`unit` 空 → `式`、id は `up_…`。
- `UnitPrice` 型: `{id, category, name, spec, unit, unitPriceYen, source?}`（`src/types.ts:138-150`）
- **単価の意味はツール側では固定されていない**（材工共・NET・提出単価のいずれでも 1 値）。何を入れたかは `出典` 列に明記する（§10）。

サンプル: `docs/samples/単価マスタ_取込サンプル.csv`

## 6. 単価引当（数量表 ← 単価マスタ）`src/pages/QuantityTablePage.tsx:48-54, 205-256`

1. 対象は **単価未設定**の数量表行のみ。マスタ側は **単価 > 0** かつ名称が空でない行のみ。
2. 比較キーは `normMatch`（全角英数記号→半角、空白除去、小文字化）を名称・規格に適用。数量表側の名称が正規化後に空の行は照合されず「見つからなかった件数」に含まれる。
3. 一致順:
   1. **名称＋規格 完全一致**（規格が両方空も一致扱い）
   2. **規格が一致し、名称が片方向部分一致**（短い方が3文字以上で長い方に含まれる）
   - 名称が一致しても規格が不一致なら **引当てない**（「規格不一致のため見送り」として件数通知）。
4. 一致時に `unitPriceYen` と `unitPriceRef`（マスタ id）を設定。

> 運用上の注意: 名称に「[新設]」等の接頭辞を付けたり規格に「同上」と書くと一致しない。数量表とマスタで **名称・規格の文字列を揃える**こと（§10 の v3 CSV は 68/68 行が段階1で一致する）。

## 9. 書出し様式

共通: `aoa_to_sheet` による値のみの出力。**数式・数値書式・罫線は入らない**（`src/io/excel.ts:102-121`）。数値は数値セル、それ以外は文字列セル。

### 9.1 数量表 `数量表_<案件名>.xlsx`（シート `数量表`） `src/pages/QuantityTablePage.tsx:260-283`

列: `分類 | 名称 | 規格 | 単位 | 数量 | 単価（円） | 金額（円） | 出典 | 備考`
- 分類ごとに行を並べ、末尾に `【<分類>　小計】` 行（金額列のみ）、最後に `合計（税抜）` 行。
- 単価未設定の行は単価・金額が空欄。単価 0 円の行は `0` が出る。出典は日本語ラベル（手入力/取込/図面拾い/機器選定）。
- 列名が §4.1 の見出しと一致するため **そのまま再取込できる**（出典は取込対象外、小計・合計行は名称が空のためスキップされる）。

### 9.2 単価マスタ `単価マスタ.xlsx`（シート `単価マスタ`） `src/pages/PriceMasterPage.tsx:138-154`

列: `分類 | 名称 | 規格 | 単位 | 単価（円） | 出典` — そのまま再取込可。

### 9.3 御見積書 `御見積書_<案件名>.xlsx` `src/io/estimateExcel.ts:19-114`

**シート `御見積書`（表紙）** 行構成: 御見積書 / 見積日（`YYYY年M月D日`） / 宛名＋敬称・自社名 / 住所 / TEL / 担当 / 「下記のとおり御見積り申し上げます。」 / **御見積金額（税込）** / 件名（`estimate.title`） / 現場（`project.siteName`） / 工期 / 見積有効期限 / 支払条件 / 【内訳サマリ】（分類, 金額）… / 集計行 / 備考（改行を含む1セル）

**シート `内訳明細`** 列: `分類 | 名称 | 規格 | 数量 | 単位 | 単価（円） | 金額（円）`
- 分類は各ブロックの先頭行にのみ出力。分類ごとの明細の後に `【<分類>　小計】`。末尾に集計行（下記）。数量は生値（プレビューは小数2桁表示）。
- 分類が0件の小計行が出るのは `mode='rough'` かつ `roughRows=[]` のときの「概算工事費」のみ。

**集計行と計算順序**（`src/logic/estimate.ts:64-79`）

| 行 | 計算 |
|---|---|
| 直接工事費 計 | Σ 分類小計（分類小計 = Σ round(数量×単価)） |
| 諸経費（直接工事費の X%） | `round(直接工事費 × overheadRatePct/100)` |
| 法定福利費（直接工事費の Y%） | `round(直接工事費 × welfareRatePct/100)`、0% は非表示 |
| 出精値引（端数調整） | `roundDown(小計, roundingUnitYen) − 小計`（マイナス計上、0 なら非表示） |
| 税抜合計 | 小計 ＋ 出精値引 |
| 消費税（Z%） | `floor(税抜合計 × taxRatePct/100)` |
| 御見積金額（税込） | 税抜合計 ＋ 消費税 |

概算見積（`mode='rough'`）は `roughRows` を `概算工事費` 1分類（単位 m2、単価=円/m²、金額=round(areaM2×costYenPerM2)）に変換して同じ計算を行う。

**この xlsx はツールへ再取込しない**（1行目がタイトル、分類が先頭行のみ、集計行が名称列に入るため）。
