# 設計積算ツール データ様式仕様書

空調換気設備 設計積算ツール（本リポジトリ）が **受け取る／書き出す** データの様式をまとめたもの。
各項目の根拠はコードの `ファイル:行` で示す（基準コミット: `4e7dea3`）。
数量表・単価マスタ・見積書の受け渡し（Excel/CSV/JSON）を他システムや社内資料とつなぐ際の参照用。

## 0. 共通事項

| 項目 | 規則 | 根拠 |
|---|---|---|
| 文字コード（CSV） | UTF-8 で読み、置換文字（�）が出た場合のみ Shift_JIS として再読込 | `src/io/excel.ts:32-42` |
| 対応ファイル | xlsx / xls / csv（SheetJS）。全シートを2次元配列化し、結合セルは左上の値を範囲に展開 | `src/io/excel.ts:1-6, 48-60` |
| セル値の正規化 | 空・null → `''`、数値は有限値のみ、真偽 → `TRUE/FALSE`、日付 → `YYYY-MM-DD` | `src/io/excel.ts:16-27` |
| 数値の解釈 | `parseNumber`: 全角数字・全角ピリオドを半角化し、`, ， 空白 円 ¥` を除去して `Number()`。変換不能は `NaN` | `src/utils/format.ts:29-37` |
| ID | `genId(prefix)` = `prefix_<Date.now()の36進><連番36進><乱数4桁>`。接頭辞: `prj`（プロジェクト）/ `qty`（数量表行）/ `up`（単価）ほか | `src/utils/id.ts:1-9` |
| 金額 | 円・税抜の整数。行金額 = `round(数量 × 単価)`（単価未設定は 0 円扱い） | `src/logic/estimate.ts:34-36` |
| 端数切捨て | `roundDown(v, unit)` = `floor(v/unit)*unit`（unit ≤ 0 は四捨五入） | `src/utils/format.ts:23-26` |
| 分類の標準値 | `機器 / ダクト工事 / 配管工事 / 換気工事 / 保温工事 / 電気工事 / その他`（自由入力も可） | `src/data/loadUnits.ts` `ITEM_CATEGORIES` |
| 出典（数量表行） | `manual=手入力 / import=取込 / takeoff=図面拾い / equipment=機器選定` | `src/types.ts:154-161` |

## 2. プロジェクトJSON（`*.sekisan.json`）

- **書出し**: プロジェクトページ「JSON書出し」。`JSON.stringify(project, null, 2)`、ファイル名 `<案件名>.sekisan.json`（案件名が空なら `project.sekisan.json`）。 `src/pages/ProjectPage.tsx:22-29`
- **読込**: 同ページ「JSON読込」。`rooms` が配列でなければ「形式が不正です」で拒否。読込時に `id` は **必ず再採番**（`prj_…`）され、`createProject()` の既定値の上に取込内容を上書きするため **欠損キーは既定値で補完**される。 `src/pages/ProjectPage.tsx:31-44`, `src/store.ts:245-248`
- 名称が空のときは `インポート` になる。

## 3. ブラウザ内永続化（localStorage）

- キー `sekkeisekisan_v1`、400ms デバウンスで保存。 `src/store.ts:22, 111-134`
- 形: `{ projects: Project[], activeProjectId, daikinModels: DaikinModel[], loadUnits: LoadUnit[], roughCosts: RoughCostUnit[], unitPrices: UnitPrice[] }`（`PersistShape`, `src/store.ts:24-31`）
- 読込時に旧データを補完: `estimate` は `defaultEstimate()` とマージ、`rooms` は `createRoom()` とマージ、`quantityItems/measurements/drawings` は `[]` 補完。 `src/store.ts:89-108`
- 保存失敗（容量不足）時はバナー表示。**PDF/DXF ファイル本体は保存されない**（メタのみ）。
- 単価マスタ・原単位・機器DBは **プロジェクトJSONには含まれない**（ブラウザ単位）。移行時は単価マスタ.xlsx を別途書出すこと。

## 6. 単価引当（数量表 ← 単価マスタ）`src/pages/QuantityTablePage.tsx:48-54, 205-256`

1. 対象は **単価未設定**の数量表行のみ。マスタ側は **単価 > 0** の行のみ（誤引当防止）。
2. 比較キーは `normMatch`（全角英数記号→半角、空白除去、小文字化）を名称・規格に適用。
3. 一致順:
   1. **名称＋規格 完全一致**（規格が両方空も一致扱い）
   2. **規格が一致し、名称が片方向部分一致**（短い方が3文字以上で長い方に含まれる）
   - 名称が一致しても規格が不一致なら **引当てない**（「規格不一致のため見送り」として件数通知）。
4. 一致時に `unitPriceYen` と `unitPriceRef`（マスタ id）を設定。

> 運用上の注意: 名称に「[新設]」等の接頭辞を付けると完全一致・部分一致とも外れやすい。数量表とマスタで **名称・規格の文字列を揃える**こと。

## 8. 図面拾い → 数量表 転記 `src/takeoff/MeasurementPanel.tsx:81-180`

| 項目 | 規則 |
|---|---|
| 対象 | 当該図面の計測のうち `kind !== 'plot'` |
| 集約キー | `label`（拾い対象名）× `unitName`。数量は合算、`spec` は重複しない値を ` / ` で連結 |
| 変換 | `category` 空 → `その他`、`name` = label、`unit` = unitName、`quantity` = 合算値（小数2桁丸め）、`source='takeoff'`、`drawingId`、`remarks` = `図面拾い: <ファイル名>` |
| 再転記 | 同じ `drawingId` の既存 `takeoff` 行を **削除して置換**。**名称｜単位** が同じ旧行に単価があれば `unitPriceYen/unitPriceRef` を引き継ぐ |
| 二重計上防止 | 数量表に `equipment` 行があり、転記対象に分類 `機器`／`換気工事` が含まれるとき確認ダイアログ（キャンセルでその分を除外） |
| 機器プロット | `kind='plot'` は数量表に転記しない（数量は機器選定→転記が正） |

### 8.1 拾いプリセット（`src/takeoff/contract.ts:37-47`）

| label | category | unit | kind |
|---|---|---|---|
| 室内機 / 室外機 | 機器 | 台 | count |
| 換気扇・全熱交換器 | 換気工事 | 台 | count |
| 吹出口・吸込口 | ダクト工事 | 個 | count |
| 角ダクト / スパイラルダクト | ダクト工事 | m | length |
| 冷媒配管 / ドレン配管 | 配管工事 | m | length |
| 部屋面積 | その他 | m2 | area |

### 8.2 スケールの様式

- PDF: 2点指定＋実寸 m 入力でページごとに `scaleByPage[pageIndex]` を設定（`scaleMPerUnit` と `pageIndex` にも同値を書き、旧データの `scaleMPerUnit` は設定時ページの値として `scaleByPage` に引き継ぐ）。値は「描画ピクセル(scale=1) → m」。適用は `scaleByPage` を優先し、無い場合は `pageIndex` のページに限り `scaleMPerUnit` を使う。スケール設定時、同ページの `length/area` 計測は再計算される（`count/plot`・`valueOverridden` は除く）。 `src/takeoff/PdfTakeoff.tsx:53-63, 735-760`
- DXF: 既定 `scaleMPerUnit = 0.001`（mm 図面）。図面単位 mm/cm/m の指定または2点実測で上書き。線分端点スナップあり。

## 9. 書出し様式

### 9.1 数量表 `数量表_<案件名>.xlsx`（シート `数量表`） `src/pages/QuantityTablePage.tsx:260-283`

列: `分類 | 名称 | 規格 | 単位 | 数量 | 単価（円） | 金額（円） | 出典 | 備考`
- 分類ごとに行を並べ、末尾に `【<分類>　小計】` 行（金額列のみ）、最後に `合計（税抜）` 行。
- 単価未設定の行は単価・金額が空欄。出典は日本語ラベル（手入力/取込/図面拾い/機器選定）。
- この xlsx は列名が 4.1 の見出しと一致するため **そのまま再取込できる**（出典は取込対象外）。

### 9.2 単価マスタ `単価マスタ.xlsx`（シート `単価マスタ`） `src/pages/PriceMasterPage.tsx:139-154`

列: `分類 | 名称 | 規格 | 単位 | 単価（円） | 出典` — そのまま再取込可。

### 9.3 御見積書 `御見積書_<案件名>.xlsx` `src/io/estimateExcel.ts`

**シート `御見積書`（表紙）** 行構成: 御見積書 / 見積日（`YYYY年M月D日`） / 宛名＋敬称・自社名 / 住所 / TEL / 担当 / 「下記のとおり御見積り申し上げます。」 / **御見積金額（税込）** / 件名 / 現場 / 工期 / 見積有効期限 / 支払条件 / 【内訳サマリ】（分類, 金額）… / 集計行 / 備考

**シート `内訳明細`** 列: `分類 | 名称 | 規格 | 数量 | 単位 | 単価（円） | 金額（円）`
- 分類ごとの明細の後に `【<分類>　小計】`。末尾に集計行（下記）。金額は数値のまま（Excel 側で再計算可）。

**集計行と計算順序**（`src/logic/estimate.ts:61-80`）

| 行 | 計算 |
|---|---|
| 直接工事費 計 | Σ 分類小計（分類小計 = Σ round(数量×単価)） |
| 諸経費（直接工事費の X%） | `round(直接工事費 × overheadRatePct/100)` |
| 法定福利費（直接工事費の Y%） | `round(直接工事費 × welfareRatePct/100)`、0% は非表示 |
| 出精値引（端数調整） | `roundDown(小計, roundingUnitYen) − 小計`（マイナス計上、0 なら非表示） |
| 税抜合計 | 小計 ＋ 出精値引 |
| 消費税（Z%） | `floor(税抜合計 × taxRatePct/100)` |
| 御見積金額（税込） | 税抜合計 ＋ 消費税 |

概算見積（`mode='rough'`）は `roughRows` を `概算工事費` 1分類（単位 m2、単価=円/m²）に変換して同じ計算を行う。
