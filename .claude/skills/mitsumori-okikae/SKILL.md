# 見積置換（PDF の元見積 → 自社見積 Excel）

## できること
- テキスト付き PDF の見積書（内容／数量／単価／金額 の表）から明細を抽出する
- 単価方式を確認し、自社テンプレート `表紙(工事)` に流し込む
  - **そのまま**: 元見積の金額をそのまま使う
  - **粗利率 X%**: 売価 = 原価 ÷ (1 − X/100)（例: 20% → 原価 ÷ 0.8）
  - **掛率 Y%**: 売価 = 原価 × Y/100（例: 115 → 原価 × 1.15）
  - 端数処理（10円／100円／1,000円単位、四捨五入／切上げ／切捨て）も選べる
- テンプレートの図形（社名テキストボックス・ロゴ・印影）、列幅・行高・罫線・印刷設定・フッターはそのまま残す
- 明細が 16 行以内なら表紙に直接記入、それ以上なら表紙は区分ごとの集計＋「内訳(工事)」シートに全明細

## できないこと
- スキャン PDF（画像のみ）。その場合は明細を手入力した JSON を作ってから Step 3 へ
- テンプレートが `表紙(工事)` と違う配置のもの（`reference/template_layout.md` のセル配置が前提）

## 必要なもの
- 元見積 PDF、自社テンプレート xlsx（ユーザーが添付する。無ければ聞く）
- Python 3.10 以上。抽出に `pdfplumber` または `pypdfium2`（どちらか）。流し込みは標準ライブラリのみ
- 見た目確認用に LibreOffice（`soffice`）があれば PDF/PNG プレビューを作れる（無くても完成品は作れる）

> **openpyxl / pandas でテンプレートを開いて保存してはいけない。** 社名テキストボックス・ロゴ・印影（図形・OLE）が消える。
> 必ず `scripts/build_estimate_xlsx.py`（ZIP 内のシート XML だけを書き換える）を使う。

## 流れ

### Step 1. 明細を抽出して見せる
```bash
python3 scripts/extract_estimate_pdf.py 元見積.pdf -o lines.json
```
- 出力の `meta`（宛名・発行者・日付・合計欄）と `lines`（title / header / item / note）を表にしてユーザーに見せる
- `warnings` が出たら、PDF を画像化して（`pypdfium2` で `page.render()`）目視照合し、`lines.json` を直す
  - よくある修正: 見出し行と明細行の取り違え、備考の混入、数量の単位（「6カ所」など）
- **合計が元 PDF の合計欄と一致することを必ず確認**（`meta.items_total` と `meta.totals`）

### Step 2. ヒアリング（まとめて 1 回で聞く）
ユーザーの最初の依頼で決まっている項目は聞き直さない。`AskUserQuestion` が使える環境では選択肢で聞く。

| 項目 | 聞き方 | 既定値 |
|---|---|---|
| 単価方式 | そのまま ／ 粗利率 X% ／ 掛率 Y% ／ 両方 | そのまま |
| 端数処理 | 単位（1／10／100／1,000 円）と 四捨五入／切上げ／切捨て | 1 円（処理なし） |
| 宛名 | 自社見積の宛先（元 PDF の宛名は自社なので、**自社の顧客名**を確認） | PDF の宛名 |
| 工事名・施工場所 | テンプレート D12／D14 | PDF のタイトル／未記入 |
| 見積 No.・見積日 | K3／J4 | テンプレートのまま／今日 |
| **値引き行** | ①元見積の値引きに他の行と同じ粗利率・掛率を掛ける ／ ②任意の金額を指定（例: 150,000 → ▲150,000）／ ③値引き行を載せない（0）。元 PDF に値引きが無くても②で追加できる。名称（値引き／出精値引 など）も併せて聞く | ① |
| レイアウト | 自動（16 行以内は表紙のみ） | 自動 |

- 値引き行は **必ず聞く**。元 PDF に値引きがあるときはその金額（例: ▲120,830）を示して「①比例 ／ ②任意の金額 ／ ③載せない」を選んでもらう。無いときも「自社の値引きを入れるか」を一言確認する
- ②③のとき、元見積の値引きは自社の原価としては残る（②は値引き行の R 列、③は合計行の O 列）。粗利額はそれを含めて計算される
- ②の金額は数式ではなく数値で入るので、粗利率・掛率・端数処理を後から変えても変わらない

### Step 3. 生成
```bash
python3 scripts/build_estimate_xlsx.py \
  --template テンプレート.xlsx --lines lines.json --out "見積書_<No>_<宛名>_<工事名>.xlsx" \
  --customer "有限会社 〇〇" --title "〇〇　エアコン更新工事" --site "施工場所" \
  --no 6330554 --date 2026-09-15 \
  --margin-pct 0 --markup-pct 100 --round-unit 1 --round-mode round
```
- `--margin-pct 20` → 粗利 20%、`--markup-pct 115` → ×1.15、両方指定で掛け合わせ
- 値引き行: 省略 = 比例配分 ／ `--discount 150000` = ▲150,000 に固定（`--discount-name 出精値引` で名称）／ `--discount 0` = 載せない
- `--layout cover|detail` でレイアウト強制、`--cover-title "【…】"` で明細欄 1 行目の見出し
- 標準出力の JSON（`sell_total` 売価合計・`cost_total` 原価合計・`layout`）を報告に使う

### Step 4. 検証
```bash
python3 scripts/render_preview.py 出来上がり.xlsx --outdir preview   # LibreOffice があれば
```
- PNG を見て、表紙 1 ページに収まっているか、明細の行数・合計・宛名を確認する
- 「そのまま」方式なら **合計 = 元 PDF の合計** になっていること
- 数式エラーの確認は xlsx スキルの `recalc.py` を **コピーに対して** 実行する（元ファイルを LibreOffice で上書きしない）

### Step 5. 納品と報告
- ファイル名: `見積書_<No>_<宛名>_<工事名>.xlsx`
- 報告に含める: 売価合計（税別）、原価合計、粗利額・率、明細行数とレイアウト、仮定した項目（施工場所・No. など）、値引き行の扱い（比例／固定額／なし と元見積の値引き額）
- 「単価設定は表紙シートの N9:N11（印刷範囲外）で後から変えられる」ことを伝える

## 出来上がりの Excel の仕組み
- 表紙 `N9` 粗利率(%)、`N10` 掛率(%)、`N11` 端数処理単位 — 黄色の入力セル（印刷されない）
- 各明細行の `M` 列（粗利率）・`P` 列（掛率）は設定セルを参照する数式。行ごとに数値を直接入れると個別に変えられる
- 売単価 `I` ＝ `ROUND(原価単価 × 掛率 ÷ (100 − 粗利率) ÷ 単位, 0) × 単位`、金額 `K` ＝ 数量 × 単価
  - 元見積に単価が無い行（1式など）は金額ベースで同じ計算
- 内部列（M〜S、印刷範囲外）: 粗利率／数量／原価単価／掛率／粗利額／原価金額／備考
- 値引き行を固定額にしたときは `K` に数値がそのまま入る（S 列に「値引き額は直接入力」）。載せないときは合計行の `O` 列に元見積の値引きが原価調整として入り、`R`（原価合計）に足される
- 表紙の `R`／`S` 列に 粗利 10／15／20／25% のときの参考売価（テンプレートの慣例）
- 開いたとき全再計算される設定（`fullCalcOnLoad`）。Excel で開いて保存すればキャッシュも更新される

## スクリプト
| ファイル | 役割 |
|---|---|
| `scripts/extract_estimate_pdf.py` | PDF → `lines.json`（罫線から列を判定。無ければ見出し位置で判定） |
| `scripts/build_estimate_xlsx.py` | `lines.json` + テンプレート → 完成 xlsx（ZIP 内 XML の書き換え） |
| `scripts/render_preview.py` | xlsx → PDF → PNG（LibreOffice。元ファイルは触らない） |
| `reference/template_layout.md` | テンプレート `表紙(工事)` のセル配置と、生成側の行の型 |
| `reference/lines_schema.md` | `lines.json` の形（手で作る／直すときの説明） |
